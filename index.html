    How to Pick a Strong Password That Holds Up

    Good password hygiene does not require memorizing cryptic strings for every website. Focus on length, true randomness, and keeping every login separate.

    Length beats clever substitutions

    Swapping an "a" for "@" or tacking "2026!" onto a favorite word is the first pattern cracking dictionaries check. Adding four extra random characters multiplies the search space far more than replacing letters in a dictionary word.

    Use at least 16 characters by default

    For email, banking, and cloud storage accounts, 16 characters across uppercase, lowercase, digits, and symbols gives roughly 104 bits of entropy. That keeps your credentials well out of reach of modern GPU cracking rigs.

    Match the preset to how you log in

    When saving a login inside a password manager, keep symbols and ambiguous characters turned on for maximum randomness. When you need to type a credential onto a smart TV, terminal, or phone screen, switch to Easy to Read to skip look-alikes like 0, O, 1, l, and I.

    Random strings vs. memorable passphrases

    A memorable and random password tool serves two different jobs. Random character strings are ideal when your browser or manager auto-fills them; if you have to memorize a master password, combine four or more unrelated words instead of shortening a character string.

    Why Client-Side Generation Matters for Privacy

    If a password generator creates credentials on a remote web server, you have to trust that server not to log requests, cache responses, or expose traffic over a misconfigured proxy. Running generation strictly inside your browser removes the server from the equation entirely.

    Keycraft uses your browser's native window.crypto.getRandomValues() interface with rejection sampling rather than Math.random(). Standard Math.random() is built for UI math and games, whereas Web Crypto pulls entropy directly from your operating system's cryptographic random pool and avoids modulo bias across character sets.

    Your recent session list lives in a plain JavaScript array in RAM. Nothing is written to localStorage, sessionStorage, IndexedDB, or analytics beacons.

    Frequently Asked Questions

    Are passwords generated on this page sent to a server or stored anywhere?

    No. Every password is generated locally on your device using your browser's built-in window.crypto.getRandomValues() API. Nothing is transmitted over the network, and session history stays strictly in temporary browser memory until you close or refresh the tab.

    How long should a strong random password be?

    For everyday accounts like email, banking, and password managers, aim for at least 16 characters mixing uppercase letters, lowercase letters, numbers, and symbols. For master passwords or sensitive developer keys, 24 to 32 characters provides a wide safety margin against offline brute-force attacks.

    What makes window.crypto.getRandomValues() safer than Math.random()?

    Math.random() is a standard pseudorandom generator meant for animations or games, not security; its internal state can sometimes be predicted. window.crypto.getRandomValues() draws entropy from your operating system's cryptographic random source, making each character genuinely unpredictable.

    When should I exclude ambiguous characters?

    Turn on Exclude ambiguous characters (0, O, 1, l, I) whenever you expect to read a password aloud, print it on paper, or type it manually onto a TV, phone, or terminal screen. For passwords stored in a password manager, leaving all characters enabled maximizes randomness.

    Should I use a random character string or a memorable passphrase?

    Use random character strings for accounts saved in a password manager, where you never need to type them by hand. If you must memorize a password—such as your laptop login or password manager master key—a long passphrase made of four or more unrelated random words is easier to recall and still hard to crack.
